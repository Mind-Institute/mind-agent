↓ regras permanentes para Vibe Code
1. Nunca duplicar person, organization, product ou concept. 2. Nunca criar tabela nova sem verificar se a entidade já existe. 3. Todo dado derivado por IA guarda source + confidence + provenance. 4. LLMs usam Agent API; não recebem SQL livre como interface principal. 5. Schemas específicos podem diferir; contratos retornados aos agentes devem ser consistentes. 6. Toda mudança de schema = declarative schema + migration + test. 7. Se a tarefa exigir mudar arquitetura, propor antes de implementar. 8. Nunca conectar coding agent diretamente ao banco de produção. 9. Tudo que altera sistema externo deve ser idempotente e auditável. 10. Não carregar contexto demais: base context mínimo + retrieval just-in-time.
